# PDF 双形态阅读：电子书（重排）⇄ 原版 PDF

> 调研与方案，2026-10-19。目标：对标微信读书 App「切换为电子书 / 切换为 PDF」，同一本 PDF 既能按原版看，也能像正式上架的 EPUB 一样重排阅读。

## 1. 微信读书怎么做的

### 1.1 K70 Ultra 实机观察（微信读书 10.2.2，导入的《AI-Agents-in-Depth-zh-CN》，2026-10-19）

截图在 `docs/research/img/weread-pdf/`。

**切换**
- 顶栏正中是图标加文字的按钮：电子书形态显示「切换为PDF」，PDF 形态显示「切换为电子书」，位置一样。不藏在菜单里，是一级操作（01、02）。
- 切换是原地进行的：同一本书，**落点对齐到同一段**（电子书在「第四/五章…」段，切到 PDF 正好是含该段的第 4 页）。
- **按书记住上次形态**：退出后再打开，回到上次选的形态。

**PDF 形态（原版）**
- 默认适宽，页面上下灰底，页码是 PDF 自身的。
- 工具栏缩减：顶栏只有返回 / 切换 / 划线笔记入口 / 分享，没有「⋯」；底栏 4 项为目录 / 进度 / 亮度 / 设置。**没有** AI、听书悬浮钮，也没有发现入口。
- 设置只有两项：「显示方向」（横屏 / 竖屏）、「翻页方式」（左右滑动 / 上下滚动）（03）。字号、主题都没有。
- 目录取自 PDF 书签：底部面板，可折叠层级，标出当前项，有「去底部」；条目保留了书签原文的怪前缀（「8 引言」「14 第 1 章…」）（04）。

**电子书形态（重排）**
- 与上架书完全同一套阅读器：字号（「仅应用到当前书籍」开关）、边距、行距、字体、首行缩进、翻页方式（06）；划词菜单为复制 / 划线 / 写想法 / 书摘 / 查询 / 听当前（07）；「⋯」面板有下载、自动翻页、书签、全文搜索、笔记、书友想法（08）；有 AI 和「听」悬浮钮。
- **目录是重新识别的**，不是 PDF 书签：更深（到 1.1.1、「实验 1-1」），去掉了书签里的怪前缀，页码按重排后的页数算；面板顶部是 搜本书 / 目录 / AI 大纲 三个页签，带「当前读到 · 添加书签」（05）。
- **重排质量问题**（同一页原版对照可确认）：
  - PDF 里普通的行尾折行被当成段落结束：「…最核心的技术｜基础。」「…两种核心范｜式，」被拆成两段，中间空一行（01）。这正是网上「段落挤乱 / 断开」抱怨的来源。
  - 折行处多出空格：「检索 什么」「模 型选型」「用 户沟通」。
  - 原版的粗体小标题（「**第四章（工具）**」）丢了粗体；列表圆点变成小位图，像素感明显。
- 推测转换在服务端完成（导入要上传云端）。轻阅本地优先，必须**全部在端上完成**。

### 1.2 公开信息补充

- 文字版 PDF 效果好；扫描版不一定能转成功，有时会出现乱码数字。英文 PDF 可以做 OCR 和中英对照，繁体可以转简体，竖排繁体 OCR 还不行。
- 用户另一类诉求是「不想识别成文字，只想看原图」。所以**随时能回到原版**是底线。

来源：豆瓣小组讨论、知乎问答、ZOL 问答、什么值得买、X 用户分享（2023–2024，非官方文档）。

### 1.3 对轻阅的启示

1. 要照搬的：顶栏一级切换按钮、原地对齐到段、按书记住形态、电子书形态完全复用正式阅读器、电子书目录重新识别。
2. 要超过它的：**行尾折行与真正段落的区分**（看行宽是否到右边界、句末标点、下一行缩进），以及中文折行不补空格、保留粗体、圆点用文字 `•` / `<li>`。这几点在 §5.2 的 3、5、7 条里，P1 必做，验收样本就用这本书的第 4 页。
3. 可以不照搬的：轻阅的 PDF 形态本来就比它强（主题、AI、听书、批注都有），不必为了「对齐」去砍功能。

## 2. 轻阅现状

| 项 | 现状 |
|---|---|
| 路由 | `readerRoute.ts`：`format === 'pdf'` 一律进 `PaperReaderView`（藏书和论文都是） |
| 引擎 | MuPDF 1.28 wasm 只出位图；PDFium 提供字符几何、链接、目录、批注 |
| 段落提取 | `paperText.ts`：基于 PDFium runs 做双栏 / 段落 / 公式占位，服务逐页翻译，每页上限 80 段，没有图片和标题层级 |
| 重排阅读器 | `ReaderView`（foliate）功能最全：主题、分页/连续滚动、听书、点睛、阅读模式、划线、智能目录 |
| 转 EPUB | `bookToEpub.ts` + `epubWriter.ts` 已有完整 OPF / nav / NCX / zip 写出，以及 `convertLibraryBook` 「另存为新书」流程 |
| 文档立场 | `paper-reading.md`：论文**始终保留原版**，不重排（公式、双栏、图表）。这条保留：论文默认不重排 |

结论：「把 PDF 变成内存 EPUB 交给 foliate」与现有 TXT/MD/HTML 的做法完全一致；缺的只是 **PDF → 语义结构** 这一段。

## 3. 实测：MuPDF 结构化文本足够当底座

`page.toStructuredText('preserve-images,segment,paragraph-break,dehyphenate')`（MuPDF ≥1.26 的版面分割 + 段落切分 + 连字符还原），node 下实测：

| 样本 | 页数 | 全书耗时 | 字符 | 位图 |
|---|---|---|---|---|
| The Little Book of Deep Learning（英文单栏，有书签） | 168 | 0.48 s | 12.4 万 | 8 |
| GPT-4 火花（中文报告，无书签） | 158 | 0.99 s | 21 万 | 54 |

- 英文正文块就是自然段（8 行 / 11 行 / 6 行），标题 `2.1 GPUs…` 字号 14，正文 10–11，页码 8，**字号层级可以直接推标题**。
- 输出是嵌套的 `structure` 块，需要递归展开。
- 中文报告里提示词、代码块是单行块（等宽字体），需要按字体 / 缩进 / 行距自己合并。
- 矢量图（折线图、流程图）不会作为 image 出现，要靠「非文字区域」裁切位图。
- 手机按 5–10 倍估算，160 页约 5–10 s，放 Worker 里分段产出完全可行。

所以底座选 MuPDF stext，**不选** PDFium runs（`paperText.ts` 的算法是给论文翻译用的，保留不动）。

## 4. 产品设计

### 4.1 形态与入口

- 一本 PDF，两种形态：`原版`（现 PaperReaderView）/ `电子书`（ReaderView + 重排 EPUB）。**不新增藏书条目**，跟 `convertLibraryBook` 的「另存新书」是两件事。
- 切换入口：两个阅读器的顶栏同一位置放一个**一级按钮**（图标 + 文字，手机也不收进「⋯」，与微信读书一致），文案 `切换为电子书` / `切换为原版`（`t('reader.pdfToReflow')` 等，中英字典同时加；按钮 `title` 固定，供 e2e 选择器使用）。转换未完成时按钮上显示进度环，点击后在转换完成前先进入已产出的章节。
- 切换时落点对齐到段（§5.5），不是只对齐到页。
- 每本书记住上次形态：`BookMeta.pdfView?: 'original' | 'reflow'`（缺省 = 按默认规则），参与同步。
- 默认规则（2026-10-19 用户确定：**文字版 PDF 默认电子书，扫描版默认 PDF**，同微信读书）。设置项 `settings.pdfReflowDefault: 'auto' | 'original'`，默认 `auto`：
  - 文字版（§4.2 判定）→ 首次打开直接进电子书形态；
  - 扫描版、乱码多、以图为主 → 原版，切换按钮置灰并说明原因（扫描版 P3 接入 OCR 后再开放）；
  - `kind === 'paper'` → 原版（与 `paper-reading.md` 的论文立场一致，可手动切）；
  - 用户手动切过的书以 `pdfView` 为准，默认规则不再覆盖；`original` 设置项供想关闭自动重排的用户使用。
- 判定时机：导入时在 Worker 里抽样评分（只看文本层，约 5 页、<300 ms），结果写入派生缓存，并立刻在后台开始转换。没有评分的旧书在首次打开时先抽样，再决定进哪个阅读器（期间显示加载态）。首次打开时转换还没完成就先读已产出的章节（§5.4）；转换失败则退回原版并轻提示一次，这本书记为 `original`。
- `readerPath()` 按 `pdfView` 决定进 `/read-paper/:id` 还是 `/read/:id?src=pdf`。

### 4.2 可重排性评分（决定默认形态、能否转）

在 Worker 里扫前 ~20 页（均匀抽样）：

| 指标 | 用途 |
|---|---|
| 有文本层页占比、每页平均字符数 | <30% 判定为扫描版 → 默认原版，切换按钮说明「扫描版暂不支持」（OCR 见 §6） |
| 乱码率（U+FFFD、私用区、CID 未映射） | 高 → 默认原版（微信读书的「乱码数字」问题） |
| 图像 / 矢量区域面积占比 | 漫画、画册、图表手册 → 默认原版 |
| 多栏比例、公式字符密度 | 论文型 → 默认原版，允许手动切 |
| 以上都通过 | 文字版 → 默认电子书 |

阈值宁可保守：误判成文字版会让用户一打开就看到坏排版，比误判成扫描版代价大。临界区（如文本层占比 30%–60%）按原版处理。

结果写入派生缓存（§5.4），不进 BookMeta。

### 4.3 电子书形态的阅读能力

全部复用 ReaderView：主题 / 字体 / 分页与连续滚动 / 听书 / 点睛 / 阅读模式 / 搜索 / 划线。额外：

- 段落右键 / 长按菜单「查看原版此页」→ 弹出该页位图（MuPDF 渲染，复用 PaperReader 的渲染函数），用来核对公式、表格。
- 图表、公式、表格以**裁切位图**出现，点开可放大；保真优先于「假重排」。

## 5. 技术方案

### 5.1 管线

```
PDF bytes ─► Worker(pdfReflow.worker.ts)
  1. MuPDF 打开; outline → 目录骨架
  2. 逐页 toStructuredText(segment,paragraph-break,dehyphenate,preserve-images,collect-styles)
     → 页 IR: Block{ page, bbox, kind:text|image|region, lines[{text,font,size,flags,bbox}] }
  3. 全书统计: 正文字号众数、行距众数、左边界众数、页眉/页脚候选
  4. 清洗与语义化 (纯函数, 可测)
  5. 非文字区域 → 按 bbox 渲染裁切 (PNG/JPEG, 2x)
  6. 按章节切分 → XHTML → epubWriter.zipEpub
─► 派生缓存 (按文件指纹)  ─► foliate 打开
```

新文件：`src/services/pdfReflow/`：`extract.ts`（MuPDF → IR，只在 Worker 中）、`structure.ts`（纯函数：清洗 / 标题 / 段落 / 章节）、`toEpub.ts`（IR → XHTML，复用 `epubWriter`）、`score.ts`（可重排性）、`anchor.ts`（位置映射）、`pdfReflow.worker.ts`。Worker 写法照抄 `keyWordsClient.ts`。

### 5.2 清洗与语义化（`structure.ts`，核心质量所在）

1. **页眉页脚 / 页码**：跨页比对顶部、底部 8% 带内的块，把数字归一成 `#` 后文本相似且 y 位置稳定，在 ≥30% 页面重复 → 删除。纯数字 / 罗马数字 / `- 12 -` 块删除。
2. **阅读顺序**：MuPDF segment 已给出列顺序；再检测双栏页（两组左边界聚类），列内自上而下。
3. **段落**：块内行合并。
   - 中日韩：行尾直接拼接不加空格；西文：加空格，行尾 `-` 按词表 / dehyphenate 处理。
   - **行尾折行 ≠ 段落结束**（微信读书的主要缺陷，见 §1.1）：一行文字伸到正文右边界附近（≥ 栏宽 90%）就算折行，直接和下一行接上；只有行未满且以句末标点结尾，或下一行有首行缩进时，才算断段。中日韩文字在折行处不补空格。
   - 块被硬换行拆成多块时（中文报告常见）：同字体、同字号、行距 ≈ 众数、上一块末行没有句末标点或未达右边界 → 合并。
   - **跨页续段**：上页最后正文块无句末标点 && 下页首正文块无首行缩进 → 合并。（这是「段落被吞 / 被断」的主因）
   - 首行缩进、段间距突变 → 新段。
4. **标题**：字号 > 正文众数 ×1.15 或粗体独占行且较短 → 标题候选；按字号聚类成 h1–h3。有 outline 时以 outline 为准（标题文本模糊匹配到页内块）；没有 outline 时，复用 `smartToc.ts` 的 `CHAPTER_RE`（第X章 / Chapter N）。
5. **列表 / 代码 / 引用**：项目符号或 `1.` 开头 → `<li>`；等宽字体连续行 → `<pre>`，保留换行；左缩进明显且字号略小 → `<blockquote>`。
6. **脚注**：页底小字号、以上标数字开头 → 收进本章末尾 `<aside epub:type="footnote">`，正文上标改成链接（foliate 已支持脚注弹窗）。
7. **样式**：`collect-styles` 的粗体 / 斜体 / 下划线 → `<b>/<i>/<u>`；颜色、字体名不保留（交给阅读器主题）。
8. **不可重排区域**：表格（`table-hunt` 命中或网格线密集）、公式（`isMathChar` 密度，复用 `paperText.ts`）、矢量图（`onVector` 聚簇 bbox）、内嵌位图 → `<figure><img/></figure>`，图下方「图 N」类说明文字作 `<figcaption>`。
9. **兜底**：一页处理异常 → 整页按 stext 原始块输出段落；还不行 → 整页位图。整本永远能打开。

所有规则都是纯函数，输入 IR、输出 IR，`npm run test:pdf-reflow` 用 JSON 化的 IR fixture 测（不依赖 wasm）。

### 5.3 章节切分与目录

- 按 outline 一级（或检测到的 h1）切成多个 XHTML，单节超过约 60 KB 再按 h2 / 页切，保证 foliate 分节加载和连续滚动性能。
- 每个块输出 `data-p="页码"`，每页第一个块加 `id="p12"`，供 §5.5 定位。
- nav / NCX 由 outline 或标题生成；封面用第 1 页位图（或藏书已有封面）。

### 5.4 派生缓存与渐进打开

- 缓存键：`文件 SHA-256（同步模块已有分块指纹）+ REFLOW_VERSION`。规则升级就递增版本，旧缓存作废重建。
- 存放：网页 Dexie 新表 `derived`；桌面 `tauri.ts` 存应用数据目录 `derived/<bookId>/reflow.epub`。**不同步、不进备份**（可再生），私密书同理。
- 渐进：Worker 先产出「目录 + 前 2 章」立刻打开，其余在后台续写；完成后静默替换（foliate 重新 open 并恢复位置）。转换进度在工具栏按钮上显示环形进度。
- 版本升级后后台重建，不打扰用户。

### 5.5 位置、进度与划线互通

- **统一进度**：`BookMeta.location` 对 PDF 保持「页码」语义；电子书形态另存 `reflowLocation`（CFI）。切换时：
  - 原版 → 电子书：页码 + 页内 y 比例 → 找 `data-p` 匹配且 bbox 最接近的块 → CFI；
  - 电子书 → 原版：当前可见首块的 `data-p` + bbox.y → 页码 + 滚动偏移。
  - `progress`（0–1）两边都按 PDF 页数折算，书架进度条一致。
- **划线**：现有 `AnnotationRec.cfi` 只服务 foliate；PDF 批注走 PaperReader 自己的结构。新增可选字段 `pdfAnchor?: { page: number; quote: string; prefix?: string }`：
  - 任一形态里新建的划线都同时写 `pdfAnchor`（电子书侧由 `data-p` + 选中文本得到；原版侧由 PDFium 字符区间得到）；
  - 在另一形态显示时，按页 + quote 文本匹配定位（W3C TextQuoteSelector 思路），匹配不到就只出现在批注列表里，标「仅在原版可见」。
  - 第一期只做「电子书形态的划线在电子书里可见 + 带 pdfAnchor」，互显放到第二期。

### 5.6 同步

- 同步 `pdfView`、`reflowLocation`、划线的 `pdfAnchor`（合并规则按字段级 LWW，同现有 `merge.ts`）。
- 派生 EPUB 不同步；另一台设备首次切换时本地重建（同一版本规则，结果确定）。

## 6. 扫描版 PDF（第三期）

微信读书在这块也不稳定，轻阅分平台渐进：

| 平台 | OCR 方案 |
|---|---|
| macOS / iOS 类 | Tauri 命令调用系统 Vision（`VNRecognizeTextRequest`，中英，免费离线） |
| Windows | `Windows.Media.Ocr`（系统语言包） |
| Linux | 检测到 `tesseract` 时调用，否则提示安装 |
| 网页 / Android | 可选下载 PaddleOCR（PP-OCRv4 mobile，onnxruntime-web，约 10–15 MB），走与「离线语音包」相同的下载 + 校验 + GitCode 镜像通道 |

OCR 结果按行带 bbox 进入同一个 IR，后续管线不变。竖排繁体先不支持（明确提示）。繁转简用 OpenCC 词表，作为电子书形态的显示选项，不改原文缓存。

## 7. 分期

| 期 | 内容 | 验收 |
|---|---|---|
| P1 | Worker + stext → IR → 清洗（页眉页脚、段落、跨页续段、标题、图片裁切）→ EPUB → ReaderView；工具栏切换；`pdfView` 记忆；页码 ⇄ CFI 位置映射；可重排性评分 + 文字版默认电子书 / 扫描版默认原版 | 文字 / 扫描判定对样本集零误判为文字版；5 类 fixture（中文小说、英文技术书、中文报告、带书签教材、双栏论文）主观评审 + 单测；160 页书在中端 Android 上 ≤3 s 出首屏，≤15 s 全书 |
| P2 | 脚注、列表、代码块、表格检测；「查看原版此页」；划线 `pdfAnchor` 互显；渐进替换；同步字段 | `test:pdf-reflow`、`test:sync-merge` 扩展；e2e：导入 PDF → 切电子书 → 划线 → 切原版 → 定位一致 |
| P3 | OCR（各平台）、繁简转换、竖排检测与提示 | 扫描版样本 CER 记录在 `docs/perf-ledger.md` 同级账本 |

## 8. 质量评估方法

- 建 `scripts/fixtures/pdf-reflow/`：每个样本存「期望段落数、标题列表、不应出现的页眉文本、跨页续段的句子」，跑 `scripts/audit-pdf-reflow.mjs` 输出指标：段落断裂率、页眉残留率、标题召回、图片丢失数。
- 对照基线：MuPDF 原始块直出（不做 §5.2）。每次规则改动必须不劣于上一版。
- 版权：fixture 用公开授权书籍（如 The Little Book of Deep Learning 为 CC BY-NC-SA）或自制 PDF。

## 9. 风险与取舍

- **公式 / 表格保真**：一律裁切成图，不做 LaTeX 还原；所以论文默认不重排。
- **wasm 内存**：MuPDF 与 PDFium 已各有一份；Worker 里再开一份 MuPDF 文档，大文件（>200 MB）在 Android 上可能 OOM → 评分阶段检测文件大小，超限只提供原版或按页段处理并及时 `destroy()`。
- **结果确定性**：派生内容不同步，两台设备必须用同一 `REFLOW_VERSION` 才能保证 CFI 互通；版本不同时只同步页码锚点，CFI 在本地重新映射。
- **与「转换为 EPUB」的关系**：P1 完成后，藏书「转换为 EPUB」菜单也可对 PDF 开放（直接导出派生 EPUB 为新书），零额外成本。

## 10. 实现状态（2026-10-20，App 侧）

代码在 `src/services/pdfReflow/`，契约测试 `npm run test:pdf-reflow`（18 项，含用 MuPDF 生成的真实 PDF）。

| 模块 | 内容 |
|---|---|
| `extract.ts` | 显示列表解释一次页面：结构化文本逐字取样式（粗体 / 斜体 / 等宽 / 数学字体）、描边伪粗体、矢量与位图外框；书签；区域裁切渲染；抽样统计 |
| `layout.ts` | 页眉页脚页码、目录页、图表（矢量聚簇 + 贴边标签 + 图与图注之间的说明）、文字表格、独立公式、代码框 / 提示框、列表圆点、引用竖线；同行碎片接回一行；段落还原与跨页续段 |
| `book.ts` | 按一级书签（或一级标题）切章、大章再切；书签层级校正标题级别并用书签的规整标题；页码锚点 |
| `epub.ts` / `convert.ts` | 只生成文字文件与图表引用（不打 zip、不渲染图）；`REFLOW_VERSION` 决定缓存与 CFI 是否通用 |
| `client.ts` / `reflow.worker.ts` | Worker 转换并保持 PDF 打开，图在章节加载时按需裁切（失败时用透明占位）；Worker 不可用时回退主线程 |
| `cache.ts` | IndexedDB `lightread-derived`：重排包（最近 12 本）+ 已渲染的图；删书时清掉 |
| `viewMode.ts` / `classify.ts` | 打开方式（手动选择 > 设置「总是原版」/ 论文 > 判定结果）与判定阈值 |

与原方案的差异：

- **图按需渲染**（§5.4 原为转换时全部渲染）：实测一张图 12–30 ms，313 页的书 180 张图在手机上要几十秒，改成章节加载时渲染并缓存。首次打开只等文字：本机 313 页约 2.4 s（4× CPU 节流下首次 5.2 s、再次 0.75 s；Worker 不受节流，真机仍需实测）。
- **打开方式按书记在本机**（`localStorage`），未参与同步：两台设备按同一判定规则得到相同默认，手动切换不跨设备。进度互通照旧——电子书形态的 `location` 写原版页码，精确 CFI 另记在本机。
- **划线互显未做**：原版批注（页内坐标）与电子书划线（CFI）各自显示。
- **中文行内空格不再删**：MuPDF 实测很少误补（313 页 28 处，多为真空格）；「模 型」类问题靠接行时不补空格解决。

已知限制：竖排、扫描版（OCR 在 P3）；复杂图示里少数标签仍会漏成短段落；表格、公式整块成图；样本《深入理解 AI Agent》443 个标题里约 12 个误判。
