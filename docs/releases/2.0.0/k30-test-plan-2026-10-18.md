# K30 轻阅 App 2.0 完整测试计划

用户于 2026-10-18 要求按此前微信读书调研的深入程度，先设计能力与测试计划，再自顶向下充分测试；不以耗时为由省略测试。读书样本使用《理想国》和 K30 已有书籍。

## 验收目标与边界

检查用户能看到的每个栏目、窗口、功能和按钮是否符合产品设计及已确认原型，验证真实结果、状态一致性、错误恢复与持续使用。主环境为 K30 原生 App，Dev 分支；浏览器和逻辑测试只补充边界，不能代替真机。

覆盖范围按运行时入口清点继续扩展，初始能力清单 **202 项**，后续按用户原型反馈新增 LIB-27、CAT-18，再根据弹窗消息需求新增 MSG-01～06，当前 **210 项**。一项可能包含多个选项／按钮，执行记录必须列明逐项结果，不能只记打开页面。动态隐藏项、样本缺失、服务不可用都保留明确状态。

## 执行顺序

1. **基线与入口盘点**：型号、系统、版本／签名／哈希、书架／偏好快照；逐页滚动清点按钮和条件入口；按真实格式选择现有书，不把书名／正文／密钥写入公共测试产物。
2. **藏书与普通阅读**：顶部到底部、一级到二级；《理想国》覆盖长文本，其他现有书覆盖格式、章节、图文；搜索、目录、书签／想法、进度、排版及恢复。
3. **阅读专项**：点睛、自动阅读、打字机、歌词、五场景、听书、背景音；组合检查和真实定时到点，至少一段 30 分钟持续听书／阅读。
4. **论文与书源**：现有 PDF／其他格式、引擎与工具；来源浏览搜索、书单、来源管理、下载／导入错误路径。已配置的服务按实际状态验收，外部故障单独归因。
5. **阅读记录与设置**：全部统计范围与详情；全部设置首页行、二级页、弹窗及每个可见选项；说明书、互传和系统文件窗口。
6. **跨流程回归**：横竖屏、前后台、键盘展开、返回层级、快速操作、进程重启、持久化；检查 ANR／崩溃／WebView 错误，核对最终数据。
7. **缺陷闭环**：复现 → 严重度 → 最小修改 → 相关回归 → 签名包覆盖 → 同设备复验。每次包变更记录哈希和重测范围，不能沿用旧包结果冒充新包已测。

## 每项的判定维度

- **UI**：文字、颜色、字号、层级、折行、对齐、长数值、安全区、遮挡、深浅色、滚动可达、图标名称、触控尺寸。
- **功能**：真实数据／渲染／音频改变，不能仅凭按钮变色；保存、取消、关闭、撤销分别验证。
- **状态**：开／关、选中／禁用、空／有数据、加载／成功／失败、暂停／恢复、二级返回、重新进入及重启。
- **边界**：最小／最大／中间值、非法／空输入、长文本、书首／书末、跨章、连续操作与组合模式。
- **证据**：设备与包、步骤、预期、实际、耗时／必要日志、私有截图路径；产品问题与自动化选择器／坐标问题分开记录。

## 数据与外部操作

现有书只用于阅读和可恢复测试。书签／想法只删除本轮新增条目；导入／删除／转换用临时副本，真实书不删除。恢复阅读位置和本轮改过的偏好，不用旧数据库整库覆盖用户新数据。账号退出、验证码发送、云端覆盖、对外发送和不可恢复操作不为覆盖率执行；无隔离条件则记受阻及原因，不能算通过。

## 结束标准

每个已发现入口都有用例及状态；核心阅读、数据保留、听书与返回链路无未解决的阻断问题；所有修复都有同设备复验。报告给出通过／失败／受阻／待测数量及未测原因，提供逐项记录和缺陷清单。存在未测或受阻项时不宣称“全部功能通过”。长时测试使用实际等待和持续观测，不加速时钟冒充真机持续使用。
